# Чат + Web Push — что осталось

Бэкенд (юзеры-сущности, чат, WS, read-receipts, unread, retention) и фронтенд
чата — готовы и провалидированы (интеграционные тесты бэка на реальном Redis,
живой прогон фронта в браузере против настоящего бэка). Ниже — то, что
обсуждали, но не доделали.

## 1. UI запроса разрешения на уведомления

Сейчас (`ChatPage.tsx`, кнопка-колокольчик в шапке) клик сразу дёргает
`Notification.requestPermission()`. Это рискованно: браузер показывает этот
диалог **один раз** — если юзер жмёт "Заблокировать", статус `denied`
остаётся навсегда, JS больше не может ни переспросить, ни отличить "ещё не
спрашивали" от "отказал".

Нужно:
- Свой диалог/шторка **перед** системным: "Присылать уведомления, когда чат
  закрыт?" + кнопки «Не сейчас» / «Включить». Настоящий `requestPermission()`
  дёргаем только по «Включить» — так не тратим единственную попытку впустую.
- Обработка `denied`: показать один раз объяснение, как включить руками
  (iOS: aA → Настройки сайта; Chrome: значок замка → Уведомления), и больше
  не приставать.
- iOS-специфика: Web Push в Safari работает только если сайт добавлен на
  Домашний экран (standalone PWA). Если открыт как обычная вкладка —
  `PushManager` может просто не быть. Надо детектить
  (`window.matchMedia('(display-mode: standalone)')` или
  `navigator.standalone`) и подсказывать "сначала добавь на Домой".
- Кнопка сейчас только *включает* подписку — нет способа её выключить из UI
  (хотя `apiClient.unsubscribeChatPush()` уже есть и работает).

## 2. Статус "кто получает уведомления"

Хотели видеть в чате список всех 4 юзеров с отметкой, у кого пуш включён.
Сейчас `push_sub:{user_id}` в Redis хранится, но нет эндпоинта, отдающего это
по всем сразу.

- Backend: `GET /chat/push/status` → `[{user_id, display_name, subscribed}]`
  (без самого subscription — только факт).
- Frontend: маленькая панель в чате (там же, где будущая шторка уведомлений)
  со списком имён + иконкой вкл/выкл.

## 3. VAPID-ключи не сгенерены

`VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY`/`VAPID_CONTACT_EMAIL` в
`esp_service/.env` ещё не заполнены — без них `/chat/push/vapid_public_key`
отдаёт 503, и подписаться нельзя. Генерируются один раз через `py-vapid`
(тянется вместе с `pywebpush`, уже в requirements.txt).

## 4. Не проверено вживую (только в headless-браузере)

- Реальный захват камеры/микрофона на телефоне (голосовые/видео-сообщения) —
  headless Chromium не даёт разрешений, кнопки проверены только на "не падает
  без permission".
- Тёмная тема ChatPage — во время браузерного теста было светлое время суток,
  визуально dark-вариант не смотрели.
- Реальная доставка Web Push (нужен HTTPS-домен, локально/http не работает).

## 5. Известные упрощения (не баги, осознанный выбор)

- Presigned URL на медиа живёт 1 час, не обновляется, если чат открыт очень
  долго — при протухании картинка/видео просто не подгрузится, надо будет
  разве что если станет реальной проблемой.
- Запись голосового/видео — тап-старт/тап-стоп, не удержание кнопки.
- Read-receipt показывается только под последним сообщением в списке (как в
  Telegram/WhatsApp), не под каждым.
- Одна push-подписка на юзера — новая с другого устройства перезаписывает
  старую.
